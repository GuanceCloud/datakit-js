# AGENTS.md

## Purpose

This repository contains the Guance browser SDK monorepo. It is an `npm` workspaces + `lerna` project that publishes multiple browser-side packages:

- `@cloudcare/browser-core`: shared runtime, transport, session, browser utilities, telemetry, serialization helpers
- `@cloudcare/browser-rum`: RUM SDK entry, event collection, replay, tracing, view/action/resource/error tracking
- `@cloudcare/browser-logs`: logs SDK entry and log collection pipeline
- `@cloudcare/browser-worker`: worker bundle embedded into the RUM build through build-time env replacement

The repo is JavaScript-first and currently uses Babel, Webpack, and Karma/Jasmine.

## Source Of Truth

When changing code, prefer source files under `packages/*/src`.

Do not hand-edit generated build outputs unless the task explicitly requires it:

- `packages/*/cjs`
- `packages/*/esm`
- `packages/*/bundle`

Those directories are build artifacts generated from `src`.

## Repository Layout

- `package.json`: top-level workspace scripts
- `lerna.json`: package version source
- `webpack.base.js`: shared bundling config for browser bundles
- `scripts/`: shared release/build utilities
- `test/unit/`: Karma config used by top-level unit tests
- `demo/`: local demo assets served by the dev server
- `docs/`: product/integration docs

Package-specific notes:

- `packages/core/src/index.js` exports the shared primitives consumed by other packages.
- `packages/rum/src/index.js` is the public RUM package entry and delegates into `boot/rum.entry`.
- `packages/logs/src/index.js` is the public Logs package entry.
- `packages/worker/src/index.js` starts the worker and is bundled into `packages/worker/bundle/worker.js`.

## Common Commands

Install dependencies:

```bash
npm install
```

Build all packages:

```bash
npm run build
```

Build browser bundles for all packages that expose them:

```bash
npm run build:bundle
```

Run the local dev server on port `8082`:

```bash
npm run dev
```

Run unit tests once:

```bash
npm run test:unit
```

Run unit tests in watch mode:

```bash
npm test
```

Build a single package:

```bash
npm run build --workspace @cloudcare/browser-rum
npm run build --workspace @cloudcare/browser-logs
npm run build --workspace @cloudcare/browser-core
npm run build --workspace @cloudcare/browser-worker
```

## Build And Test Behavior

- Top-level `npm run build` executes `lerna run build --stream`.
- `rum` and `logs` build `cjs`, `esm`, and browser bundle outputs.
- `core` builds `cjs` and `esm` only.
- `worker` builds only its bundle output.
- `scripts/build-env.js` injects build-time constants such as `SDK_VERSION`.
- `WORKER_STRING` is generated by building `packages/worker` and inlining `bundle/worker.js` into consumers. If a change affects worker behavior, rebuild the dependent package too, not just `worker`.
- Unit tests run through Karma + Jasmine in `ChromeHeadlessNoSandbox`.
- Current test discovery is `packages/*/+(src|test)/**/*.spec.js`. There are few existing specs, so manual verification may still be necessary.
- When adding or expanding unit tests, explicitly call out any performance issue discovered during the work, such as slow bundling, unstable long-running specs, heavy setup/teardown, or code paths that noticeably degrade test runtime.

## Editing Guidelines

- Prefer minimal, source-level changes in `packages/*/src`.
- Keep module format consistent with surrounding code. The repo uses plain JavaScript and existing style conventions rather than TypeScript source.
- Preserve public entry points and exported names unless the task explicitly requires an API change.
- If a change affects any public API, init configuration, or externally observable return shape, you MUST update the published type declarations under `packages/*/types/*.d.ts` in the same change. Do not leave runtime behavior and `.d.ts` out of sync.
- Check package boundaries before moving shared logic; `core` is the shared dependency layer.
- If touching bundling or build-time env behavior, inspect `webpack.base.js`, `scripts/build-env.js`, and `scripts/replace-build-env.js` together.
- Do not commit or expose registry tokens from `.npmrc` or other local config.

## Verification Expectations

After non-trivial changes, prefer this sequence:

1. Run the most targeted package build first.
2. Run `npm run test:unit` if the change may affect shared runtime behavior.
3. If the change affects RUM or Logs bundle behavior, also run `npm run build:bundle` or the relevant package build.
4. If the change affects browser behavior, validate through `npm run dev` with the demo app when practical.

## Working Tree Safety

- The worktree may contain user changes unrelated to the current task.
- Do not overwrite or revert existing modifications unless explicitly asked.
- Before editing a file with local changes, inspect the diff and apply a surgical patch.
